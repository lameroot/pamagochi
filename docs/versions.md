### Почему Prisma 6, а не 7

npm-реестр на дату фиксации версий отдаёт `prisma@7.9.1` как `latest`. Prisma ORM 7 вносит несовместимые изменения: обязательные driver adapters (`@prisma/adapter-pg`), новый генератор `prisma-client` с обязательным `output`, перенос `datasource.url`/`directUrl` из `schema.prisma` в `prisma.config.ts`, отсутствие автозагрузки `.env`. Это существенно увеличивает риск и объём работы для MVP-скелета и слабее задокументировано в текущих туториалах NestJS + Prisma. Решение: зафиксировать `6.19.3` — последнюю стабильную версию ветки 6.x, полностью совместимую с классическим `schema.prisma` (`datasource.url`, `prisma-client-js`). Апгрейд на Prisma 7 стоит делать отдельной задачей после того, как экосистема (гайды NestJS, adapters) стабилизируется.

## Проверка совместимости

- Node.js 24 LTS официально поддерживается NestJS 11, Prisma 6.19, Vite 8, Playwright 1.62.
- Fastify 5 — официальный адаптер `@nestjs/platform-fastify@11` поддерживает Fastify 5.
- Prisma 6.19 поддерживает PostgreSQL 17 и Node.js 24.
- Vite 8 требует Node.js >= 20.19 — совместимо с Node 24.
- React 19.2 совместим с Vite 8 через `@vitejs/plugin-react@6`.
- Phaser 4.2 не требует конкретной версии React/Vite — интегрируется как обычная JS-библиотека через `createGame.ts`.

Фактический вывод (на дату фиксации версий):

```
├───────────────────┼─────────┼────────┼────────────────────────────────┤
│ @prisma/client    │ 6.19.3  │ 7.9.1  │ @pamagochi/database            │
├───────────────────┼─────────┼────────┼────────────────────────────────┤
│ @types/node (dev) │ 24.13.3 │ 26.1.2 │ @pamagochi/api, pamagochi      │
├───────────────────┼─────────┼────────┼────────────────────────────────┤
│ prisma (dev)      │ 6.19.3  │ 7.9.1  │ @pamagochi/database            │
├───────────────────┼─────────┼────────┼────────────────────────────────┤
│ typescript (dev)  │ 5.9.3   │ 7.0.2  │ @pamagochi/api, @pamagochi/... │
└───────────────────┴─────────┴────────┴────────────────────────────────┘
```

Все пять записей — намеренные, не забытые:

* **`prisma` / `@prisma/client` (6.19.3, не 7.9.1)** — см. подробное обоснование выше в этом файле (обязательные driver adapters, новый генератор, `prisma.config.ts`, отсутствие автозагрузки `.env` в v7).
* **`typescript` (5.9.3, не 7.0.2)** — TypeScript 7 — это новый Go-порт компилятора, выпущенный совсем недавно; `typescript-eslint`, декораторы NestJS (`emitDecoratorMetadata`) и остальной инструментарий ещё не имеют широкой проверенной поддержки TS7 в production на момент фиксации версий.
* **`@types/node` (24.13.3, не 26.1.2)** — типы должны соответствовать реальной мажорной версии Node.js в рантайме (24 LTS). `@types/node@26` описывает API Node.js 26, которого в проекте нет и не будет до отдельного апгрейда рантайма.
* **`@fastify/static` (9.3.0, не 10.1.2)** — `@nestjs/platform-fastify@11.1.28` (актуальная стабильная версия NestJS) объявляет peer-зависимость `@fastify/static: "^8.0.0 || ^9.0.0"`; версия 10.x приводит к предупреждению о несовместимых peer dependencies и потенциальным поломкам `useStaticAssets()`, используемого Swagger UI.

Апгрейд любого из этих пакетов стоит делать отдельной задачей, когда экосистема (NestJS peer-зависимости, typescript-eslint, гайды Prisma) догонит соответствующий major.
